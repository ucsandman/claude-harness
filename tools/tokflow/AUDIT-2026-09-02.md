## 1. Where the tokens go today

Over 8 days (2026-08-26 to 2026-09-02) the transcript miner parsed 162 main sessions + 131 subagent transcripts (100,456 JSONL lines, 0 bad) and found 11,150 deduped assistant turns, 846 user prompts, 13,856 tool calls. Raw input-side volume was 2.10B tokens, of which 97.4% was cache_read; price-weighted (0.1x read, 1.25x creation, 1x fresh) that is 273M effective tokens, and output (6.8M tokens, 32.6% thinking) is only ~11% of spend even at 5x, so input context is the lever. **Fixed context per interactive session is p50 81,801 tokens (mean 86,499, p10 44,700, p90 163,517; n=115 clean starts)**, which is double the ~40k headless figure in memory; the gap is MCP schemas, plugin SessionStart hooks, the 30 KB skill_listing (129 entries, 7,495 tokens, injected 1.28x per session across 251 sessions) and CLAUDE.md/MEMORY.md. Of that fixed context only 41,878 B (10,470 tokens) is file text we own (CLAUDE.md+agnostic-rules 20,122 B, MEMORY.md 6,255 B, skill descriptions 6,963 B, plugin descriptions 5,092 B, agent descriptions 1,749 B, SessionStart hook stdout 822 B). **Per turn**: mean context 188,137 tokens over 45 turns per session (p50 18, p90 135; n=158), so one token added to fixed context costs about 1 + 0.1 x 45 = 5.5 effective tokens per session, and 51.3% of all effective spend (140M) comes from the 3,904 turns above 200k context, a consequence of the no-auto-compact choice Wes already made (0 compactions in 158 sessions; one 352-turn session ran 119k/turn early and 449k/turn late). **Per tool call**: hook-injected text is effectively zero (9,427 PreToolUse injections carried 0 B; 7,077 PostToolUse carried 6,179 B total); tool_result text was 23.7 MB (5.9M tokens) across 13,866 results, Bash 11.3 MB and Read 8.2 MB, and 658 images cost ~987k tokens (per-image, not bytes/4). **Per spawn**: general-purpose subagents pay 51,351 tokens (opus, n=37; sonnet 53,117, n=59) before their first tool call versus 17,511 for opus-owner (n=4), 13,344 floor for haiku-scout (n=9), 21,567 floor for sonnet-implementer (n=6); Workflow agent() defaults to agentType workflow-subagent at 51,162 (n=46 sonnet) versus 27,379 when agentType sonnet-implementer is passed (n=10, same run family as this audit). 1,861 of 1,873 workflow spawns since 08-26 (99.4%, across 50 runs) used the expensive default; subagents are 22.9% of all tokens (482M raw), and 101 general-purpose Agent-tool spawns happened in the window (0.64 per session).

- Explicit low/medium effort per Workflow stage: not refuted, but no measurement exists (sonnet output mean 22,907 tokens/spawn at high, n=4, no low-effort comparison). Run one controlled A/B before adopting.
- Per-tool-call hook trimming, Bash output caps, duplicate-call guard, image downscaling: measured and found not to pay (0 B per call; 40/7,165 Bash results over 20 KB; 102k tokens per 8 days of dupes; API resizes images anyway).
